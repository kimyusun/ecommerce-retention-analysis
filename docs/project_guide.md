# 프로젝트 이해 가이드

이 문서는 이커머스 데이터 분석 프로젝트를 스스로 설명할 수 있도록 정리한 해설서다. 포트폴리오 README가 결과 중심이라면, 이 문서는 왜 그런 분석을 했고 어떤 판단을 했는지 이해하는 데 초점을 둔다.

## 1. 이 프로젝트는 무엇인가

영국 온라인 쇼핑몰의 거래 데이터를 분석해 서비스의 성장성과 고객 유지 상태를 판단한 프로젝트다.

핵심 질문은 세 가지다.

1. 매출, 고객 수, 주문 수는 성장하고 있는가?
2. 신규 고객은 첫 구매 이후 다시 구매하고 있는가?
3. 비회원 주문은 단순한 일회성 매출인가, 아니면 회원화 또는 B2B 리드 기회인가?

이 질문들이 중요한 이유는 이커머스 성장을 단순 매출 합계만으로 설명하기 어렵기 때문이다. 매출이 늘어도 그 성장이 신규 고객 증가 때문인지, 기존 고객 재구매 때문인지, 특정 시즌의 고액 주문 때문인지에 따라 실행 전략이 완전히 달라진다.

## 2. 데이터 구조

원본 데이터는 `data/raw/ecommerce_data.csv`이며, 거래 라인 단위 데이터다. 한 행은 주문 하나가 아니라 주문 안의 특정 상품 구매 기록을 의미한다.

| 컬럼 | 의미 | 분석 시 주의점 |
|---|---|---|
| `InvoiceNo` | 주문 번호 | `C`로 시작하면 취소 거래로 보고 제거 |
| `StockCode` | 상품 코드 | 5자 미만 코드는 일반 상품이 아닌 특수 처리 코드로 보고 제거 |
| `Description` | 상품명 | 일부 결측 존재 |
| `Quantity` | 수량 | 0 이하 값은 반품/취소성 거래로 제거 |
| `InvoiceDate` | 거래 일시 | 월별/일별 지표 계산 기준 |
| `UnitPrice` | 단가 | 0 이하 값 제거 |
| `CustomerID` | 고객 ID | 결측이면 비회원 주문으로 해석 |
| `Country` | 구매 국가 | 국가별 확장 분석에 활용 가능 |

중요한 점은 이 데이터가 라인아이템 단위라는 것이다. 예를 들어 주문 하나에 상품 5개가 들어 있으면 `InvoiceNo`는 같지만 행은 여러 개가 된다. 그래서 주문 수를 계산할 때 `COUNT(*)`를 쓰면 실제 주문 수가 아니라 상품 라인 수를 세게 된다. 주문 수는 `COUNT(DISTINCT InvoiceNo)`, 고객 수는 `COUNT(DISTINCT CustomerID)`처럼 집계 기준을 명확히 해야 한다.

## 3. 전처리 기준

분석에서는 모든 지표에 같은 전처리 기준을 적용했다.

| 전처리 | 이유 |
|---|---|
| `InvoiceNo`가 `C`로 시작하는 거래 제거 | 취소 거래를 매출에 포함하지 않기 위해 |
| `StockCode` 길이 5자 미만 제거 | 배송비, 수수료, 조정 코드 등 일반 상품이 아닌 항목 제거 |
| `Quantity <= 0` 제거 | 반품 또는 비정상 수량 제거 |
| `UnitPrice <= 0` 제거 | 무상/오류성 단가 제거 |
| `Quantity IN (80995, 74215)` 제거 | 대량 이상치가 월별 지표를 왜곡하는 것을 방지 |

이 기준이 중요한 이유는 기존 산출물 일부에서 2011년 1월 일평균 매출 값이 달랐기 때문이다. 원인은 `Quantity = 74215`인 이상치 주문을 제거했는지 여부였다. 제거하지 않으면 2011년 1월 일평균 매출은 `21,677.66`, 제거하면 `19,187.86`이다. 포트폴리오에서는 제거 후 값을 기준으로 사용했다.

## 4. 월별 KPI 분석

월별 KPI는 다음 세 가지로 계산했다.

| 지표 | 정의 |
|---|---|
| 일평균 매출 | 하루 매출 합계를 월별로 평균 |
| 일평균 고객 수 | 하루별 고유 고객 수를 월별로 평균 |
| 일평균 주문 수 | 하루별 고유 주문 수를 월별로 평균 |

월합이 아니라 일평균을 사용한 이유는 월별 날짜 수가 다르기 때문이다. 31일인 달과 28일인 달을 단순 월합으로 비교하면 영업일 수 차이가 섞인다. 그래서 전체 날짜 캘린더를 만들고 거래가 없는 날도 0으로 채운 뒤 월별 일평균을 계산했다.

핵심 결과는 2011년 하반기부터 일평균 매출, 고객 수, 주문 수가 함께 상승했다는 점이다. 특히 2011년 11월과 12월 초에 피크가 나타난다. 이는 연말 선물 수요 또는 도매성 주문이 강해지는 시즌성으로 해석할 수 있다.

## 5. 코호트 리텐션 분석

코호트 분석은 고객을 최초 구매월 기준으로 묶고, 그 이후 몇 개월 뒤에 다시 구매했는지 보는 방식이다.

예를 들어 2011년 3월에 처음 구매한 고객을 `2011-03 코호트`로 묶고, 이들이 +1개월, +2개월, +3개월에 다시 구매했는지 계산한다.

이 분석에서 비회원은 제외했다. 비회원은 `CustomerID`가 없기 때문에 같은 사람이 다시 구매했는지 추적할 수 없기 때문이다.

핵심 결과는 대부분 코호트가 첫 구매 후 1개월 차에 크게 이탈하고, 이후 20~30%대에서 유지된다는 점이다. 즉 이 서비스에서는 첫 구매 직후 30일 안에 재구매를 유도하는 캠페인이 중요하다.

주의할 점도 있다. 데이터가 2010년 12월부터 시작되기 때문에 `2010-12 코호트`는 실제 신규 고객이 아닐 수 있다. 이전부터 구매하던 고객이 데이터 관측 시작일 때문에 처음 구매한 것처럼 보일 수 있다. 그래서 이 코호트의 높은 장기 리텐션은 좋은 신호이지만, 순수 신규 고객 리텐션으로 과대 해석하면 안 된다.

## 6. 비회원 주문 분석

`CustomerID`가 없는 주문은 비회원 주문으로 정의했다. 비회원 분석에서는 세 지표를 봤다.

| 지표 | 의미 |
|---|---|
| 비회원 주문 비중 | 전체 주문 중 비회원 주문이 차지하는 비율 |
| 비회원 매출 비중 | 전체 매출 중 비회원 주문 매출이 차지하는 비율 |
| 비회원 주문당 평균 매출 | 비회원 주문 1건당 평균 매출 |

2011년 11월의 비회원 주문 비중은 3.96%로 낮다. 그런데 비회원 매출 비중은 21.65%로 높고, 비회원 주문당 평균 매출은 2,895.41이다.

이 말은 비회원 주문이 자주 발생하는 소액 주문이 아니라, 적게 발생하지만 매출 기여가 큰 주문이라는 뜻이다. 그래서 이 구간은 단순히 회원가입을 강제할 문제가 아니라 고액 비회원 구매자를 회원 또는 B2B 리드로 전환할 기회로 보는 것이 적절하다.

## 7. 최종 인사이트

이 프로젝트의 핵심 메시지는 다음과 같다.

1. 2011년 하반기부터 서비스의 성장성은 뚜렷하다.
2. 하지만 성장 피크에는 시즌성과 고액 비회원 주문이 섞여 있으므로 단순 고객 증가로만 보면 안 된다.
3. 리텐션은 첫 구매 후 1개월 차에 크게 떨어지므로 초기 30일 관리가 중요하다.
4. 11월 비회원 주문은 주문 수보다 매출 기여도가 높아 회원화 또는 B2B 리드화 전략이 필요하다.

## 8. 실행 제안

| 제안 | 이유 |
|---|---|
| 4분기 사전 주문 캠페인 | 11월 피크를 우연한 시즌 효과가 아니라 반복 가능한 매출 기회로 만들기 위해 |
| 고액 비회원 결제 후 회원화 | 구매 중에는 방해하지 않고, 구매 후 영수증/재주문 혜택으로 데이터 확보 |
| 7/21/30일 리마케팅 | +1개월 리텐션 하락을 완화하기 위해 |
| 약한 시즌 별도 캠페인 | 봄·여름 저조 구간을 보완하기 위해 |

## 9. 면접이나 포트폴리오에서 설명하는 방법

좋은 설명 순서는 아래와 같다.

1. 이 프로젝트는 단순 매출 분석이 아니라 성장성, 재구매, 회원화 기회를 함께 본 이커머스 분석이라고 말한다.
2. 먼저 데이터가 라인아이템 단위라서 주문 수와 고객 수를 집계할 때 기준을 명확히 해야 했다고 설명한다.
3. 전처리 기준을 통일했고, 특히 2011년 1월 이상치 때문에 숫자가 달라지는 문제를 해결했다고 말한다.
4. 월별 KPI로 하반기 성장과 11월 피크를 확인했다고 설명한다.
5. 코호트 리텐션으로 첫 구매 후 1개월 차 이탈이 크다는 점을 발견했다고 말한다.
6. 비회원 분석에서 주문 비중은 낮지만 매출 비중은 높아 고액 비회원 전환 전략이 필요하다고 결론낸다.

## 10. 한계

이 분석은 거래 데이터만 사용했다. 유입 채널, 캠페인 정보, 회원가입 시점, 상품 카테고리, 실제 B2B 여부는 확인할 수 없다. 따라서 11월 피크가 어떤 캠페인 때문인지, 어떤 상품군 때문인지는 추가 데이터 없이는 확정할 수 없다.

다음 단계로는 상위 SKU 분석, 국가별 비회원 고액 주문 분석, 상품군별 시즌성 분석을 추가하면 좋다.
